# Context OS v1.2.0

Context OS 1.2.0 adds first-class Devin cloud sessions and native Windows Devin
CLI support. A project can keep its identity, state and reviewed handoffs in Git
when work moves between supported agents. The [1.x compatibility contract](https://github.com/conorbronsdon/agent-context-os/blob/v1.2.0/docs/compatibility-contract.md)
is unchanged.

## Devin cloud sessions

Live runs on snapshot build `sbj-f04a9b4dd96a43ff806501a2bedd34bf` passed
instruction, skill and lifecycle controls. Setup, update and end each produce a
proposal; Devin applies it after receiving the operator's exact-digest approval.
The harness checks pushed commits and permitted paths, compares each applied
tree and receipt with an independent kernel replay, and checks receipt timing.
A fresh session recovers the saved next action from a handoff branch without
pending proposal artifacts.

Cloud sessions require a repository blueprint. The [Devin guide](https://github.com/conorbronsdon/agent-context-os/blob/v1.2.0/adapters/devin/README.md)
and [cloud evidence](https://github.com/conorbronsdon/agent-context-os/tree/v1.2.0/docs/evidence/devin-cloud-2026-10-08)
record the tested boundaries. Devin Review remains an instruction-compatible
review surface, separate from lifecycle hosts.

## Native Windows Devin CLI

CLI `3000.11.3` is covered on Windows 11 from PowerShell, alongside Linux
(WSL2). Native Windows host, hook and lifecycle controls passed, including
setup, start, update, end, wrong-digest and stale-proposal rejection, and a
fresh-session handoff. In CLI lifecycle runs, the operator applies the reviewed
proposal outside Devin; these runs do not establish model enforcement of
exact-digest approval.

Windows Devin reads the real OS profile despite `HOME` overrides. The opt-in
harness never writes profile fixtures. It checks locally hashed lines of the
real global Claude instructions to establish that they stayed out of the
recorded sessions. User-level skill metadata remains visible. macOS has no live
Devin CLI evidence.

The shipped import guard disables foreign agent configuration. Hooks and
portable skills reuse the active Bash to avoid selecting the Windows WSL
launcher from PowerShell's path. The setup advisory directs agents to
`$context-setup`; the interactive terminal installer is a separate workflow.
See the [Windows evidence](https://github.com/conorbronsdon/agent-context-os/tree/v1.2.0/docs/evidence/devin-cli-windows-2026-10-08).

## Release assets and upgrades

Download all five attached assets from the immutable release. Begin with
`agent-context-os-template-v1.2.0.OFFLINE-VERIFY.md`. The attached template tar
is the canonical workspace; GitHub's generated source archives are repository
snapshots.

Release qualification exercises the pinned published baselines in
`scripts/qualify-release-migration.py`, including 1.1.1 → 1.2.0 upgrades,
schema-v1 and legacy migrations, selected profiles, personalized file conflicts,
rollback, lock exclusion, journal recovery, post-commit doctor failure and fresh
setup on Linux and Windows. These synthetic tests are separate from native
adapter evidence. Windows extraction cannot verify POSIX executable bits.

Source version 1.2.0 remains a candidate until its immutable release is
published. Until then, use the published 1.1.1 assets or the source setup path.
Cursor IDE remains experimental.
