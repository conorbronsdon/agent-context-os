# Context OS v1.1.1

Context OS 1.1.1 adds Devin CLI as the seventh first-class lifecycle adapter, beside
Claude Code, Codex, OpenClaw, OpenCode, Hermes Agent and Cursor CLI. Devin cloud
sessions remain experimental, Devin Review is a compatibility surface, and Cursor
IDE remains experimental. The [1.x compatibility contract](https://github.com/conorbronsdon/agent-context-os/blob/v1.1.1/docs/compatibility-contract.md)
is unchanged.

## Devin

Devin CLI support is scoped to `3000.11.3` on Linux (WSL2). The template ships:

- `.devin/config.json`, which stops Devin importing Claude, Cursor, Windsurf,
  Copilot, OpenCode and Zed configuration. Without it Devin loads the root
  `CLAUDE.md` and the user's `~/.claude/CLAUDE.md` beside `AGENTS.md`.
- `.devin/hooks.v1.json`, which restores the lifecycle advisories at session
  start and after writes. The hooks never block. Devin injects hook context only
  for `SessionStart`, `UserPromptSubmit` and `PostToolUse`, so the write
  reminder arrives after the write.

Invoke `/context-setup`, `/context-start`, `/context-update` and `/context-end`
in Normal mode. Devin's `/update` is a self-update. Apply only the exact digest
you reviewed. The [Devin guide](https://github.com/conorbronsdon/agent-context-os/blob/v1.1.1/adapters/devin/README.md)
records observed permission limits: Accept Edits ignores project write denies,
Bypass ignores project denies, and broad user or local allows override a project
deny.

Live evidence backs each claim:

- CLI host, hook, allowlist and lifecycle runs: setup, start, update and end
  with exact-digest operator apply and a fresh-session handoff.
- A cloud session on a public synthetic fixture: root instructions were
  discovered and the user-only skill did not fire implicitly. The web composer
  failed to send the explicit `@skills:` turn twice. The identical request
  succeeded through Devin CLI `3000.11.3`, resuming the same cloud session.
  Cloud lifecycle proposal/apply has no evidence yet, so cloud sessions stay
  experimental.
- Devin Review on a public synthetic fixture: it reported a canary-bearing
  finding required by `REVIEW.md`, and separately by the shipped `AGENTS.md`,
  and reported no issues on benign changes. Review reads repository
  instructions only; it is not a lifecycle host.

Native Windows is not covered. There, Devin reads the real profile's
`~/.claude` regardless of `HOME`.

## Other changes

- Read-only briefings expose source IDs and revisions, and
  `start --expect-source-revision` fails when an expected revision is missing or
  different.
- Briefing ages, hashes and excerpts describe the same source snapshot.
- Root `CLAUDE.md` imports shared `AGENTS.md` instructions when both exist.
- The first-handoff guide shows how to record self-reported reviewers, decision
  IDs and supersession links with existing Markdown fields.

## Upgrades and qualification

Upgrade a schema-v1 or schema-2 workspace with its verified installed bundle and
the verified 1.1.1 bundle, as described in
[workspace configuration](https://github.com/conorbronsdon/agent-context-os/blob/v1.1.1/docs/workspace-configuration.md).
Release qualification runs published 0.14, 0.15 and 1.0 upgrades, including
workspaces that the published 1.0.0 kernel itself migrated and installed, personalized
conflict refusal, rollback, lock exclusion, journal recovery, post-commit doctor
failure and fresh setup on Linux and Windows. These are synthetic tests, separate
from native adapter evidence and human onboarding. Source version 1.1.1 alone does
not establish a published release.

Download all five attached assets from the immutable release. Begin with
`agent-context-os-template-v1.1.1.OFFLINE-VERIFY.md`; the attached template tar is
the canonical workspace. GitHub's generated source archives are different assets.

Version 1.1.0 was qualified and tagged but never published; its tag and draft
remain as a retired, unpublished record. Use 1.1.1.
