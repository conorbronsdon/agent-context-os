# Context OS v0.13.0

Context OS can now live in its own repository while attaching an ordinary
application repository as read-only working evidence. The release also adds a
versioned workspace composition contract and a file-backed coordination board
for concurrent agent runs.

## What changed

- **Attach an external project safely.** `project attach` and `project rebind`
  create digest-bound proposals that keep ContextRoot writable and WorkingRoot
  read-only. Session workflows report the two Git evidence scopes separately.
- **Reconcile a workspace deliberately.** Workspace schema v2 records the
  selected component profile and detached bundle digest. `workspace reconcile`
  plans compatible migration, composition, rollback, and recovery before files
  change.
- **Coordinate concurrent work.** The new board records bounded claims, lease
  expiry, successor handoff, and degraded references in repository state rather
  than a central service.
- **Expand the optional catalog.** Shortcut, Slack, and GitLab MCP entries now
  disclose their OAuth scopes, data access, side effects, and confirmation
  boundaries. Nothing is installed or enabled by Context OS.

Claude Code, Codex, and OpenClaw remain first-class hosts. Hermes Agent,
Cursor, and Devin remain experimental adapters; this release does not claim
installed-client conformance beyond their documented evidence.
