# Working instructions

Read `current-work.md` and `handoff.md` before starting work. Treat them as
context to verify against the project files and the user's latest instructions.
If they disagree, identify the conflict before relying on the disputed claim.

## During work

- Follow the project's existing instructions and permission boundaries.
- Read the relevant files before proposing changes. Load more context only as needed.
- Keep durable project constraints in `current-work.md`; link to detailed sources.
- Distinguish verified facts, assumptions, and unresolved questions.
- Record verification honestly: what ran, its result, and what remains unchecked.

## When asked to save progress or finish

Update `current-work.md` to reflect the active objective, blockers, and next action.
Replace `handoff.md` with a short account of this session: changes, verification,
unfinished work, and the first action for the next session. Preserve unresolved
items until they are resolved or explicitly dropped. Do not copy the whole task
list into the handoff or append a transcript. Follow the user's review preferences.

Update the date only when reviewing or changing the file. Use a session date
supplied by the host, user, or a checked clock. If none is available, write
`unknown`; never guess or reuse a previous session's date as the current one.

Never record secrets or raw private exports. Commit or publish only when
authorized by the user.
